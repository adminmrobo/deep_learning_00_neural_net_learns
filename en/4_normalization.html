Normalization — put numbers on the same scale

Character counts are in the thousands; link counts run from 0 to 12. We look at normalization, which puts numbers of different sizes on the same scale. In the mail data, the moment we add character count the hard set cracks, but without standardization the model can't use that information. We also try regularization, which has a similar name.

01

NormalizationNormalization

It lines up the numbers' center (mean) and scale (spread). You can do it once on the inputs beforehand, or every time inside the layers of a neural network.x̂ = (x − μ) / σ

1Why we need it

In the mail data, character count runs from 400 to 4,400 and link count from 0 to 7. If we feed them in as is, changing the character-count weight by just 0.001 shakes the score z a lot, while the link-count weight has to change a lot before z barely moves. Then it's hard to fix both weights with a single learning rate. Normalization moves every feature to around mean 0, standard deviation 1 so they can be compared on the same scale.

InputNumbers of all different sizes
OutputAround mean 0, spread 1
EffectFast, stable learning

In plain wordsIt's a standard score. If math is out of 100 with an average of 60, and English is out of 10 with an average of 6, you can't compare raw scores of 80 and 8 directly. Change them to "how many standard deviations above average" and you can see both subjects on the same scale.

2Formula · Input normalization
Standardization:   x̂ = (x − μ) / σ,    μ = (1/n) Σ xᵢ,   σ = √[(1/n) Σ (xᵢ − μ)²]
Min-max normalization:   x̂ = (x − min) / (max − min)   → 0 ~ 1
μ (mu)
Mean. The value you subtract to move the center to 0
σ (sigma)
Standard deviation. The value you divide by to make the spread 1
σ²
Variance. The square of the standard deviation

Try it with numbersCharacters: μ = (1,200 + 400 + 4,400 + 2,000) / 4 = 2,000,  σ = √[(800² + 1,600² + 2,400² + 0²) / 4] = 1,496.7
Mail ③: (4,400 − 2,000) / 1,496.7 = 1.60  → "1.6 standard deviations longer than average"
Links: μ = 3, σ = 2.55  → Mail ②: (7 − 3) / 2.55 = 1.57. Now both features are on the same scale, between −1.2 and +1.6.

A rule for real work: compute μ and σ from the training data only, and use those same values for the test data and new mail. Computing them with the test data mixed in is like peeking at the answers.

The contour lines show the height of the cost J, and the center is the bottom. The weight w₁, which multiplies big numbers like character count, changes J a lot even when it moves a little, so before normalization the valley is steep on one side and long and narrow. 4Normalization inside layers · Which values get averaged together?

Even if you normalize only the inputs, after passing through layers the values end up in all different sizes again. So neural networks also normalize between layers. There are several methods, but the formula is the same; only the group of values used to compute the mean and variance differs. Pick a method and click a cell in the input table. The outlined cells are that cell's reference group.

5Formula · Four layer normalizations
x̂ = (x − μ) / √(σ² + ε),    y = γ x̂ + βBatchNorm, LayerNorm and GroupNorm all use this formula. ε is a very small number added to avoid dividing by 0, and γ and β are learned values that "stretch and shift back."
RMSNorm:   y = γ · x / √(mean(x²) + ε)It doesn't subtract the mean; it only divides by the root mean square (RMS). That saves one step of computation.

BatchNormSame channel, all examples in the batch and all spatial positions (H × W)Yes. At inference it uses running averages collected during trainingγ, βImage CNNs (with large enough batches)
LayerNormAll features within one example (token)No. Same rule for training and inferenceγ, βTransformers, recurrent neural networks
GroupNormWithin one example, one bundle (group) of channelsNo. The designer sets the number of groups Gγ, βCNNs with small batches (object detection, segmentation)
RMSNormAll features within one token, without subtracting the meanNoγRecent large language models (the LLaMA family, etc.)
6Interpretation

BatchNorm asks, "Is this channel value big or small compared with the other examples in this batch?" It works well when the batch is big enough, but if the batch is small ("Shrink the batch to 1" in the exercise above) or sentence lengths vary, the statistics become unstable.

LayerNorm doesn't look at other examples; it only compares the features within one token. Because the rule is always the same no matter the batch size, it became the standard for transformers. RMSNorm skips subtracting the mean to make it lighter, and GroupNorm splits channels into a few bundles, a middle ground between LayerNorm and per-channel normalization.

A tip for remembering: draw the table and circle the cells that get averaged together, and you can predict how it behaves. If the circle spans several examples, it depends on the batch; if it stays within one example, it doesn't.

!Same word in Korean, a different meaning

In Korean, both are sometimes called by the same word, which is confusing. Normalization on this page means normalization (matching the size of values). Regularization is something else: in Korean it usually gets its own name, translated here as regularization, and it is a technique that adds one more penalty to the cost function from Part 3.

Jreg = J + λ Σ wᵢ²L2 regularization: it penalizes weights that grow too big, which reduces overfitting, where the model memorizes the training data. λ is the strength of the penalty.

2Interpretation · You need both the information and the scale

With only links and exclamation marks, the hard set stayed near the baseline (Part 2). Newsletters average 4,150 characters and phishing spam 1,540, so adding character count splits the two groups apart. In the full code, test accuracy jumps from 0.683 → 0.983.

But this information can only be used after standardization. Character counts are in the thousands and link counts run from 0 to 12, so the same learning rate is too big for one and too small for the other. With η = 1, the character-count weight jumps by thousands in one step and the sigmoid gets stuck at 0 or 1; make η very small, and the link and exclamation weights barely move. Standardize, and the three features share the same scale, so one learning rate moves them all just right.

Compute μ and σ from the training data only. If you include the test data, it's like peeking at the test questions in advance (data leakage). In scikit-learn, wrapping them as make_pipeline(StandardScaler(), model) keeps this order automatically.

03

Regularization · Penalizing the weightsRegularization (L2)

Let's try a different technique with a similar name: regularization. How do the weights and accuracy change when we change the penalty strength λ?

Fruit Fly Researcher

Penalize too hard and everyone starves. Just enough is key!

1Raise λ and the weights shrink

Hard set, three standardized features, logistic regression (η = 0.5, 300 steps). Adding λ/2 · Σw² to the cost adds λw to the gradient, which pulls the weights a little toward 0 at every step.

Jreg = J + (λ/2) Σ wᵢ²,    w ← w − η (∂J/∂w + λw)

λ = 0 · 0.01 · 0.1 · 0.5 · 2

Weights (standardized scale)
Accuracy

2Interpretation · Regularization is a brake against overfitting

Regularization makes the model choose "weights only as big as truly needed." When there are thousands of features and little data, a model easily memorizes even the chance quirks of the training mail (overfitting). Penalizing the weights makes that memorizing expensive, so the rules that remain also work on new mail.

Our mail data has only three features, so there's almost no overfitting, and weak regularization doesn't change the score. On the other hand, if λ gets too big, even useful weights get squashed and accuracy drops to the baseline. In the full code too, with C = 1/λ at 100 and 1 the test score was 0.983, and at 0.01 it was 0.733.

AnalogyHow many cm students' heights in a class are usually away from the average.

AnalogyPeeking at the test questions in advance. The score is high, but it isn't real skill.
MeaningA mistake where information from the test data (e.g. mean, standard deviation) leaks into training, so the score looks better than it really is.
Layer normalization
Batch
AnalogyA stack of answer sheets graded at one time.
MeaningThe group of examples used together for one weight update. How many there are is the batch size.
BatchNorm
AnalogyComparing scores in one subject against the whole class. If the class is small, the comparison wobbles.
MeaningNormalizes each channel using the mean and variance across all examples in the batch. It depends on the batch size.
LayerNorm
AnalogyComparing one student’s scores in many subjects against that student’s own average.
MeaningNormalizes using the mean and variance of all features inside one example (token). It does not depend on the batch and is the standard in transformers.
GroupNorm
AnalogySplitting one student’s subjects into humanities and science groups, and comparing only within each group.
MeaningSplits the channels inside one example into G groups and normalizes each group. Used in CNNs with small batches.
RMSNorm
AnalogyA volume knob that ignores the average and only sets "how loud is it overall".
MeaningNormalization that does not subtract the mean and only divides by √mean(x²). It needs less computation than LayerNorm.
Regularization
Regularization
AnalogyA fine for overeating. When weights get too big, they get penalty points so the model cannot memorize the workbook answers.
MeaningA technique that adds a penalty for weight size (e.g. λΣw²) to the cost function to reduce overfitting (regularization).
Overfitting
AnalogyA student who only memorized the answers to past exams. Perfect on old exams, but stuck on new questions.
MeaningA state where the model fits the training data well but does worse on new data.
