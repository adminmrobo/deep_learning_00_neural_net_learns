1

Perceptron — multiply, add, and fix it when wrong

Back to the educator notes on the Part 1 page

6 check questions · 2 points each (12 total). Correct answer + one-sentence reason = 2 points, correct answer only = 1 point, wrong answer but key reason stated = 1 point.

Question 1  What happens to the weights when the perceptron predicts correctly?

  1. ① They get a little bigger
  2. ② They get a little smaller
  3. ③ They don't change ✔ Answer

ExplanationWhen it's right, y − ŷ = 0, so w ← w + 0. A perceptron learns only from wrong examples.

Points2 points

Question 2  What happens to the decision boundary line when you change the bias b?

  1. ① The slope stays the same; only its position shifts in parallel ✔ Answer
  2. ② The position stays the same; only the slope rotates
  3. ③ The line becomes a curve

Explanationb shifts the line's position in parallel. The direction the line tilts is set by w.

Points2 points

Question 3  Which problem can a single perceptron never solve?

  1. ① Two groups that can be split by a line
  2. ② A problem that can't be split by a line, like XOR ✔ Answer
  3. ③ A problem with 3 or more inputs

ExplanationOne line can't separate XOR, where diagonal corners share the same class. You need stacked layers with a bending activation function.

Points2 points

Question 4  What does a perceptron with w = (1, 1), b = −5 say about a mail with 2 links and 2 exclamation marks?

  1. ① Spam (ŷ = 1)
  2. ② Normal (ŷ = 0) ✔ Answer
  3. ③ Can't tell

Explanationz = 1×2 + 1×2 − 5 = −1 < 0, so ŷ = 0: normal.

Points2 points

Question 5  On the hard set, the perceptron's test accuracy came out lower than the baseline (0.667). What is the best explanation?

  1. ① The two groups overlap and can't be split by one line, so it didn't converge, and the line where it stopped happened to be bad ✔ Answer
  2. ② There is a bug in the code. A perceptron always beats the baseline
  3. ③ Raising the epochs to 1,000 always gets 1.0

ExplanationWith overlapping data, every time the line turns to fix one mail, another mail goes wrong. It never converges, and the final line is just where the set number of rounds ran out.

Points2 points

Question 6  What does it mean that the easy set's baseline is 0.714?

  1. ① Just answering "normal" for every mail gets 71.4% of the test mails right ✔ Answer
  2. ② The perceptron got 71.4% right
  3. ③ 71.4% is spam

Explanation75 of the 105 test mails are normal, so answering only "normal" gives 75/105 = 0.714. Accuracy should always be read alongside this number.

Points2 points

Activation functions — you need a bend to stack layers

Back to the educator notes on the Part 2 page

5 check questions · 2 points each (10 total). Correct answer + one-sentence reason = 2 points, correct answer only = 1 point, wrong answer but key reason stated = 1 point.

Question 1  What happens if you change every hidden layer's activation function to f(z) = z?

  1. ① It learns more complex curves
  2. ② Stacking layers is the same as a single line ✔ Answer
  3. ③ Learning becomes impossible

ExplanationW₂(W₁x) = (W₂W₁)x, so without a bend, any number of stacked layers equals one linear function.

Points2 points

Question 2  Which fits an output layer that must give probabilities for three classes: normal, spam, and ads?

  1. ① ReLU
  2. ② Step function
  3. ③ Softmax ✔ Answer

ExplanationSoftmax turns the outputs of all classes into probabilities that add up to 1.

Points2 points

Question 3  Why do the early layers learn poorly when you stack many sigmoid hidden layers?

  1. ① Its gradient is at most 0.25, and these get multiplied layer after layer, shrinking ✔ Answer
  2. ② Because the output can be negative
  3. ③ Because the computation is too slow

ExplanationWhen the gradient is passed backward through each layer, numbers of 0.25 or less keep getting multiplied, so it approaches 0. This is the vanishing gradient, and it's why hidden layers mostly use ReLU.

Points2 points

Question 4  With f(z) = z, the output for input (0, 0) becomes 2, a wrong "spam". Why?

  1. ① Without a bend, h₁ − 2h₂ = −(x₁ + x₂) + 2, which is just a single line ✔ Answer
  2. ② The weights were chosen badly. With other weights, a linear network could solve it
  3. ③ Because there are only two hidden neurons

ExplanationStacked linear layers simplify back into a single linear expression (a line). XOR can't be split by a line, so a bending activation function is a must.

Points2 points

Question 5  On the hard set, switching the activation function to ReLU still leaves test accuracy near the baseline. What is the best reason?

  1. ① The two kinds of mail are mixed in the same spots on the links–exclamation plane, so no boundary shape can split them ✔ Answer
  2. ② ReLU cut negatives to 0 and lost information
  3. ③ 8 hidden neurons is too many

ExplanationBends solve shapes a line can't handle (XOR), but they can't solve overlap where the same input has different answers. A new feature is needed (character count in Part 4).

Points2 points

Cost functions and gradient descent — measure how wrong, then go downhill

Back to the educator notes on the Part 3 page

6 check questions · 2 points each (12 total). Correct answer + one-sentence reason = 2 points, correct answer only = 1 point, wrong answer but key reason stated = 1 point.

Question 1  The answer is spam, but the model said the spam probability was 0.01. What is the cross-entropy loss?

  1. ① About 4.6 (very large) ✔ Answer
  2. ② About 0.01 (very small)
  3. ③ Exactly 1

Explanation−log 0.01 ≈ 4.6, a very large penalty for a confidently wrong prediction.

Points2 points

Question 2  At the current position, the gradient ∂J/∂w is +3. What does gradient descent do to w?

  1. ① Increase it
  2. ② Leave it
  3. ③ Decrease it ✔ Answer

ExplanationA positive gradient means increasing w also increases J, so you must decrease w to bring J down.

Points2 points

Question 3  During training, the cost J doesn't drop but keeps growing. What should you suspect first?

  1. ① The learning rate is too small
  2. ② The learning rate is too large ✔ Answer
  3. ③ There is too much data

ExplanationIf the step is too big, it jumps over the valley floor and lands higher on the other side; as this repeats, J grows.

Points2 points

Question 4  The softmax output is (normal 0.66, spam 0.24, ads 0.10) and the answer is spam. What is the cross-entropy loss?

  1. ① −log 0.24 ≈ 1.43 ✔ Answer
  2. ② −log 0.66 ≈ 0.42
  3. ③ The sum of −log over all three probabilities

ExplanationMulti-class cross-entropy looks only at the probability given to the correct class: −log 0.24 ≈ 1.43.

Points2 points

Question 5  Why is the cost curve for mini-batch 32 bumpier than for full batch?

  1. ① Each batch computes the gradient from a different 32 mails, so the direction wobbles a little ✔ Answer
  2. ② Because the learning rate grows automatically
  3. ③ Because mini-batches don't use a cost function

ExplanationThe average gradient of 32 mails is a 'sample' of the full average gradient, so it differs a little. That's why it wobbles, but it makes more updates per epoch and goes down faster.

Points2 points

Question 6  On the hard set, the training cost won't go below about 0.5. What is the best explanation?

  1. ① Gradient descent reached the valley floor, but with one line the floor is high for this data ✔ Answer
  2. ② The learning rate is too small, so it's still going down
  3. ③ The cross-entropy was computed wrongly

ExplanationThe lowest value of the cost function is set by the model and the data together. No line can confidently get the mixed mails right, so the floor is high.

Points2 points

Normalization — put numbers on the same scale

Back to the educator notes on the Part 4 page

6 check questions · 2 points each (12 total). Correct answer + one-sentence reason = 2 points, correct answer only = 1 point, wrong answer but key reason stated = 1 point.

Question 1  If the average character count is 2,000, what is a mail with 2,000 characters after standardization?

  1. ① 0 ✔ Answer
  2. ② 1
  3. ③ 2,000

Explanation(x − μ)/σ = (2,000 − 2,000)/σ = 0. A value equal to the mean becomes 0 after standardization.

Points2 points

Question 2  Which method works by the same rule in training and inference even with a batch size of 1?

  1. ① BatchNorm
  2. ② LayerNorm ✔ Answer
  3. ③ Neither

ExplanationLayerNorm averages only over the features within one token, so it works by the same rule no matter the batch size.

Points2 points

Question 3  How is RMSNorm different from LayerNorm?

  1. ① It also looks at other examples in the batch
  2. ② It splits channels into groups
  3. ③ It doesn't subtract the mean ✔ Answer

ExplanationRMSNorm doesn't subtract the mean; it only divides by √mean(x²), and usually learns only γ, without β.

Points2 points

Question 4  If you feed in character count without standardization and train with η = 1, the cost shoots up. What is the best reason?

  1. ① Character counts are in the thousands, so the score z gets huge, and the sigmoid sticks at 0 or 1 and is confidently wrong ✔ Answer
  2. ② Because character count has nothing to do with spam
  3. ③ Because η = 1 is too big for any data

ExplanationIn the gradient (p − y)x, x is in the thousands, so the character-count weight jumps hugely in one step. After standardization every feature is around 1, so the same η moves them all evenly.

Points2 points

Question 5  The μ and σ for standardization were computed from training and test data combined. What's the problem?

  1. ① Information from the test data leaks into training, so scores can look better than they really are (data leakage) ✔ Answer
  2. ② The computation gets slower
  3. ③ No problem. More data makes μ and σ more accurate

ExplanationCompute μ and σ from training data only, and use those same values on test and new data. Wrapping it in a Pipeline keeps this order automatically.

Points2 points

Question 6  Raising λ to 2 dropped test accuracy to near the baseline. Why?

  1. ① The penalty was so strong that even useful weights were pushed toward 0 ✔ Answer
  2. ② Because regularization caused overfitting
  3. ③ Because standardization was turned off

ExplanationWhen all weights get small, the score z bunches up near 0, and the model gives nearly the same probability for almost every mail. Use validation data to find a 'just right' λ.

Points2 points

Lab — train while changing just one dial

Back to the educator notes on the Part 5 page

This part is assessed with lab tasks instead of check questions. The numbers in the sample results below were actually produced with the reference code (Python 3 · scikit-learn 1.9); the browser lab is a teaching implementation, so its numbers may differ slightly. If a student's numbers differ but the direction is the same, it's correct.

Basic task 1 · Adding information

TaskHard set, default dials (ReLU · standardization on · η 0.1 · 8 hidden · 200 epochs), features 2 → 3, seeds 0–2.

Sample resultReference code f5_lab.py (5 seeds): 2 features 0.647 ± 0.019 → 3 features 0.970 ± 0.012, baseline 0.667. Beginner e5 (seed 0): 0.650 → 0.983.

Sample interpretationWith links and exclamation marks alone, it is about the same as or below the baseline, because newsletters and phishing spam are mixed in the same spots on these two features. Adding character count separates the two groups, and test accuracy rises sharply. The difference is much larger than the wobble (±), so it is hard to call it luck.

Scoring points① Did they change only one feature? ② Did they interpret it against the baseline? ③ Did they judge by looking at the wobble across several seeds?

Basic task 2 · Without matching the scales

TaskIn the 3-feature setup from task 1, turn off only standardization.

Sample resultReference code: 0.970 ± 0.012 → 0.667 ± 0.000 (same as the baseline 0.667). In the browser, the cost may swing wildly or stop at infinity.

Sample interpretationAccuracy exactly equal to the baseline means it answered every test mail with one side (normal). Character count (in the thousands) dominates the score, so the sigmoid sticks at 0 or 1 and the gradient barely reaches links and exclamation marks. The information was there, but the scale kept it from being used.

Scoring points① Did they change only standardization? ② Did they read what 'same as baseline' means (answering only one side)? ③ Did they explain it with the Part 4 principle (big numbers × same learning rate)?

Challenge task 1 · Data that needs a bend

TaskIn Make your own, turn on 'Spam as two groups on both sides of normal mail' (e.g. normal links 5 · exclamation marks 5, spam links 9 · exclamation marks 9, spread 1), and compare linear vs ReLU with 2 features.

Sample resultBrowser example (seed 0): linear is near the baseline; ReLU is clearly above it. Numbers vary by setup, so check the student's record sheet.

Sample interpretationWhen spam sits on both sides of normal mail, one line can only cut off the spam on one side. A ReLU hidden layer folds the plane to bring both sides together, making a band-shaped boundary. It's the same idea as XOR in Part 2.

Scoring points① Did they include the distribution plot? ② Did they change only the activation? ③ Did they connect it to XOR?

Challenge task 2 · Learning rate and epochs

TaskEasy set, 50 epochs, with η 0.001 · 0.01 · 0.1 · 1.

Sample resultReference code (200 epochs): η 0.1 → 1.000, η 0.001 → 0.977 ± 0.019. With 50 epochs, η 0.001 barely lowers the cost and may stay near the baseline.

Sample interpretationWith too small an η, the curve goes down slowly and almost flat, and doesn't reach the floor within the set epochs. With too large an η, it swings at first, but on this easy set it usually comes down in the end. Tell 'slow' apart from 'diverging' by the shape of the cost curve.

Scoring points① Did they change only η? ② Did they compare the shapes of the cost curves? ③ Did they mention how epochs affect the result?

Models that draw lines and models that give probabilities — regions, probability, numbers

Back to the educator notes on the Part 6 page

4 check questions · 2 points each (8 total). Correct answer + one-sentence reason = 2 points, correct answer only = 1 point, wrong answer but key reason stated = 1 point.

Question 1  On the hard set, SVM and logistic had the same test accuracy. So why is only logistic's cross-entropy finite?

  1. ① In mixed areas, logistic says “about 50/50”, so even when wrong, it isn't very surprised ✔ Answer
  2. ② Because logistic got more right
  3. ③ Because SVM has its own special way to compute cross-entropy

ExplanationCross-entropy grows as the probability given to the answer gets lower. A region-type model in effect gives wrong mails a probability of 0, so −log 0 = ∞.

Points2 points

Question 2  Before tossing a coin, what is the entropy when the chance of heads is 0.5 versus 0.99?

  1. ① Larger at 0.5 (most hesitant) ✔ Answer
  2. ② Larger at 0.99
  3. ③ They are the same

ExplanationEntropy is 'hesitation before looking'. It peaks at 50/50 (0.693) and gets closer to 0 the more it leans to one side.

Points2 points

Question 3  Why is a kernel SVC still 'region-type' even after it can make island-shaped zones?

  1. ① Only the zone's shape got freer; the answer is still “inside or outside” ✔ Answer
  2. ② Because using a kernel automatically gives probabilities
  3. ③ It is region-type only when γ is small

ExplanationRegion-type and probability-type differ not by the boundary's shape but by 'whether it says how sure it is'.

Points2 points

Question 4  Linear regression predicted “4.2 reports ± 2.7 reports”. What is closest to the meaning of ± 2.7?

  1. ① The width of a bell-shaped distribution centered on the prediction. About 95% of actual values fall in this range ✔ Answer
  2. ② The model was wrong 2.7 times
  3. ③ The chance of spam is 27%

ExplanationSeen as a distribution, linear regression's value on the line is the mean, and the standard deviation σ of the residuals is the bell's width. About 95% falls within μ ± 1.96σ.

Points2 points

Lecture guidelines

This part is animation-based, so it comes with lecture guidelines alongside the check questions.

1. Don't let the motion be mistaken for learning itself

  • First tell students that each frame is the real state after one epoch (step), and frames are not blended together.
  • Point out that the kernel SVC in the browser is an approximation using random Fourier features. For official results, use the SVC numbers from f6.

2. Scores go with the baseline

  • For classification, the baseline is 'answer only with the larger side'; for regression, 'answer only with the mean'.
  • On the hard set, don't call a small gap like 0.683 vs 0.667 a win. It flips with the seed and the split.

3. Common misconceptions by model

  • 'SVM gives probabilities' → No. It only gives scores (distances); probabilities come from an add-on step like Platt.
  • 'Using a kernel makes it probability-type' → Only the shape of the zones changes.
  • 'Fitting 0/1 with linear regression makes it classification' → Predictions go outside 0–1, and the line gets dragged by far-away data. Use logistic for classification.

4. Entropy made easy

  • Entropy = hesitation before looking; cross-entropy = surprise after looking. Call the two words by the same names all the way through.
  • Writing a table (0.5 · 0.9 · 0.99 · 1) on the board and having students fill in the −log values with a calculator speeds up understanding.

5. Limits of the pictures

  • We could draw it because there are two features. Real filters use thousands of features.
  • Colors in outer areas with no data are the model's guess (extrapolation). Be careful especially with large-γ kernels.

6. Classroom tips

  • Sample plan (50 min): 01 analogies 10 min → 02 training side by side 10 min → 04 entropy map 15 min → 05 coin and bell 10 min → wrap-up 5 min.
  • 03 Kernel flows naturally if you first show Part 2's XOR again.
  • 04 needs tapping on the map, so a PC or tablet is recommended.
